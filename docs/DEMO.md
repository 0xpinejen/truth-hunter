# 演示与真实调查案例

## 比赛讲解顺序（约三分钟）

1. 首页介绍“先看证据”的原则，展示「线索检索 · 腾讯元宝搜索」与官方来源图标。
2. 从最近调查或档案馆打开已保存的真实搜索：展示实际返回的 10 条线索、RequestId、耗时、原始返回。无需重复耗费额度；强调搜索成功不代表事实已核验。
3. 首页任选一个“体验虚构演示案例”，展示创建、事件、报告、原文引用与证据不足结论。四个案例全部为固定虚构资料。
4. 打开证据关系图，说明实线只表示已保存的声明与引文绑定；独立性仍未确认。
5. 将案例加入追踪，再打开持续追踪列表；手动重新核验需再次发起任务。没有后台自动付费搜索。
6. 展示 Markdown 导出、最近调查、真实/演示统计及设置。DeepSeek 和截图识别已接通；优先展示 TESTING.md 中通过当前 v2 审计的真实案例。旧版撤回报告只用于讲解审计修正。

参考图中的统计、配额和裁决是视觉示意；当前页面以实际记录替代。用户身份显示为本地研究员，不伪造已登录账户、订阅和付费计划。

## 已能运行的虚构演示

1. 启动后端与前端，进入首页。
2. 点击“运行演示”。界面进入调查室，显示 fixture 标识。
3. 观察真实写入数据库的演示步骤事件；它们描述本地测试流程，不声称外网操作。
4. 查看“证据不足”报告与虚构条款原文；点击“原文证据 1”定位证据。
5. 导出 Markdown 或回到档案馆重新打开任务。

这只验收产品与编排闭环，不能用于证明元宝 API、真实网页或事实裁决已经成功。

## 完整闭环的演示重点

从当前通过审计的真实案例打开调查室，依次展示：真实截图选择器 → 每条来源的原文与网络记录 → 模型调用 ID 和 token 用量 → 支持/反驳对比 → 复核者、出处组、裁决范围 → 最新版本 Markdown。所有原始搜索、模型提议及历史报告均保留。

接口域名和版本发布日期属于“第一方文件对自身记录的记载”范围，不能把同机构多篇文档说成多个独立来源。火星建筑等宽泛声明若没有直接相关证据，应展示如何把模型过度推断的反驳片段降为背景，并保留证据不足。

复核编辑器可提交 manual 或 assistant，页面与导出均显示实际角色。修订必须基于当前报告 ID，服务器拒绝过期提交。最终报告的 COMPLETED 表示复核流程结束，不是“所有消息都已被证明为真”。

主推跨机构案例：从档案馆打开“2017年8月21日发生过日食”的含NASA/ESA检索线索版本（任务 `a58f7022b69a4a909f541f2725003971`）。先展示 NASA/EPIC 对地月影与 ESA/Proba-2/SWAP 太阳遮挡的实际页面，再展开出处依据和两组计数；强调独立性来自不同平台、仪器与数据链，不只是两个网站名称。事前预报与其他同机构网页不纳入计数。对应最终 Markdown 已导出到 `artifacts/independent-eclipse-final-report.md`。
