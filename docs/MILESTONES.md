## 优先级与下一步

1. **解除 Phase 2 阻塞**：元宝专用密钥已由用户授权创建并配置，真实搜索已通过；DeepSeek 配置与真实调用已通过；已用可选 HTTPS DNS、公网固定连接和离线渲染处理 fake-IP，不放行私网。不得通过允许私网访问来“通过”测试。
2. **只跑一条真实消息**：最多 3 次搜索（最多两条普通查询＋一条反证查询），快速模式最多 3 页，深度模式最多 6 页，总时限 180 秒，最多两项并行任务。对每次实际成功和失败保留事实记录。
3. **审查证据链**：核对真实 SearchRun→Source→Snapshot→Evidence→Claim→Report。确认引用逐字存在、URL 是实际最终地址、截图不是占位图。
4. **扩展 Phase 3**：出处提议、引用链定位和显式复核已实现，继续验证跨机构独立来源与对抗材料；独立性未知时不能按独立信源计数；给出相关性、时效性、原始源和反证要求；通过人工复核或明确的事实核验规则，逐步开放非 INSUFFICIENT 最终裁决。
5. **用真实数据完善 Phase 4/5**：传播关系图、回放、导出、三个可重复案例和生产环境边界。

## 定义“完成”

`COMPLETED` 在 fixture 模式中仅代表演示流程完成，绝不计入“完成核验”。真实调查在模型阶段保持 PARTIAL / INSUFFICIENT；显式复核后可为 COMPLETED，表示流程完成复核，不保证每条声明都能定真伪。至少两个经确认的独立出处组可按规则裁决；第一方文件只在明确定义的自身记载范围内裁决，不能冒充多源独立验证。安全审计可显式撤回不可信取证的旧结论。状态、页面、导出都携带 `data_mode`，健康检查的“已配置”不代表“已连通”。
